## 修复主题色字体颜色显示错误（18:26 完成，Debug+Release 编译通过）

**问题**：标题 1 等 Word 内置样式用主题色（Accent1 蓝色），直接读 Font.Color 返回不可靠字面值（0x0000A5FF 解码后是橘色），窗口颜色按钮显示错误。

**关键事实（编译验证）**：本机 interop Word 15.0 的 WdColorIndex 枚举缺 wdColorIndexAutomatic/wdColorIndexTheme* 成员；Word.Document 无 Theme 属性——不能走主题色方案 API。

**方案（临时文档采样法）**：
- `GetWordFontColor(font, doc)`：ColorIndex 数值 < -1000 判定为主题色 → `ResolveThemeColor()`；ColorIndex==0 或 Color==automatic → 黑色；否则 ColorTranslator.FromOle 直接读
- `ResolveThemeColor(colorIndexValue)`：创建不可见临时文档（Documents.Add Visible=false），插入字符设置同款 ColorIndex，读取渲染后 Font.Color 得实际 RGB，删除字符关闭文档；静态字典 _themeColorCache 按 ColorIndex 缓存，避免反复建文档
- 已知局限：临时文档用默认主题，若用户文档用自定义主题，颜色可能略有差异（但远好于错误的字面值）
- 需要用户在真实 Word 中验证标题 1 颜色是否显示为蓝色

## 主题色采样二次修复（18:32 完成，Debug+Release 编译通过）

**用户反馈**：打开窗口后中文字体显示为空、颜色不对。

**根因 1（严重）**：旧采样 `rng.Text = "A"` 后直接复用 rng 设置 ColorIndex——range 在 Text 赋值后可能失效变成整个文档，导致主题色被批量应用到整篇文档（文档被污染，需 Ctrl+Z 撤销）。

**修复**：采样改用"按位置构造的精确 Range"：先记录 insertPos = rng.End，插入后 `doc.Range(insertPos, insertPos+1)` 只操作 1 个字符，读取后删除该字符；临时文档 fallback 同步修复；增加 resolved 标志（采样执行成功即信任结果，不再用 result==Black 误判 fallback）。

**根因 2**：NameFarEast/NameAscii 对主题字体样式返回 null 或空白字符串，`?? ` 只处理 null 不处理空串 → 下拉框显示空。

**修复**：新增 SafeGetFontName 回退链（NameFarEast → NameAscii → Name，Trim 且跳过空白），中文字体/西文字体均按回退链读取。

## 主题色读取最终方案：应用样式采样（18:44 完成，Debug+Release 编译通过）

**用户反馈**：标题 1 在 Word 显示 365f91，窗口显示黑色。

**根因**：样式级颜色若为主题色，Font.Color 返回 wdColorAutomatic（"自动"），且**设置 ColorIndex 后 Font.Color 仍返回自动**——主题色在样式层无法展开。黑色 = 走了"自动→黑"分支。

**正解（关键认知）**：主题色**应用到文本后会在文本层展开为实际 RGB**。因此：插入采样字符 → **应用目标样式（set_Style(ref object)，Range.Style 是 ref 属性 CS1545）** → 读文本层 Font.Color → 得实际颜色（365f91）→ 删除字符。

**实现**：
- `GetWordFontColor(font, doc, styleName)`：Font.Color 非自动直接读；自动 → `ResolveStyleRenderedColor(doc, styleName)`
- `ResolveStyleRenderedColor`：文档末尾插入"A"（位置精确 Range，UndoRecord 包裹）→ set_Style → 读 Font.Color → Delete；失败回退临时文档版；按样式名缓存（_styleColorCache，窗口会话级）
- `RefreshFromDocument` 时清空缓存（切换文档主题变化）
- 弃用 ColorIndex 数值判断方案（主题值无法可靠展开）
